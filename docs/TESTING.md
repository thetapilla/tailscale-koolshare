# 测试指南

本文说明可重复执行的验证方法与覆盖范围。构建依赖和产物目录见 [构建与发布](BUILD.md)，日常排障见 [使用指南](USER-GUIDE.md#常见问题)。

## 自动化检查

在仓库根目录执行。Go 辅助程序与真实核心测试需要先完成 [核心及辅助程序构建](BUILD.md#构建与验证)。

| 命令 | 验证范围 |
| --- | --- |
| `python3 -m unittest discover -s tests -p 'test_*.py' -v` | 后台生命周期、配置和防火墙；安装迁移；更新事务；打包与发布逻辑 |
| `node tests/test_ui.js` | 异步请求、超时、任务关联、轮询、按钮状态和文本渲染 |
| `python3 tools/test_helper.py` | Linux 上的签名与哈希、归档路径和文件类型、架构、LocalAPI、超时、原子链接及日志脱敏 |
| `python3 tools/test_busybox.py` | BusyBox 1.25.1 ash 的脚本语法与后台、安装、核心更新回归测试；安装测试使用受限 applet 命令目录 |
| `python3 tools/smoke_core.py` | 两种目标架构的真实压缩程序、daemon、辅助程序及 LocalAPI 冒烟测试 |
| `python3 tools/smoke_install.py --lifecycle` | 六份正式安装包的安装、重装、迁移及平台一致性；真实 ARM 核心、辅助程序、签名、userspace 服务启动与页面任务写入 |

脚本测试将可写路径放入临时目录，用模拟命令替代固件服务、配置及防火墙操作。发布逻辑测试模拟 GitHub 操作。BusyBox 测试工具校验官方源码归档后构建兼容性环境，版本和校验值由 [测试脚本](../tools/test_busybox.py) 固定。回归测试仅允许显式列出的命令，禁用 `command` 内置命令，且不提供 `od`、`mkfifo`、`mktemp` 和外部 `timeout`。核心架构检查、日志管道、临时文件及命令超时由随包辅助程序处理；防火墙测试覆盖旧版无等待参数和新版支持等待参数的分支。

安装包冒烟测试从 `dist/` 解包，执行包内原始安装器与运行库，使用真实签名、辅助程序和核心校验安装结果。平台信息、软件中心配置、空间、防火墙和定时任务使用模拟环境；安装一致性检查保持服务停用。`--lifecycle` 另行启用 userspace daemon，验证日志管道、LocalAPI、设置应用和页面任务文件，无需 TUN 或加入 Tailnet。该测试使用容器 Shell，与 BusyBox 回归测试分别覆盖不同边界。

真实核心冒烟测试使用原生架构或 QEMU，在无网络的临时容器中运行。它覆盖 userspace daemon 和未登录状态，不需要加入 Tailnet。

## 发布产物检查

完成构建、签名和打包后，检查同批安装包及核心元数据：

- 六个标准插件包和 `SHA256SUMS` 齐全，文件名及包内版本与 [VERSION](../VERSION) 一致。
- 每个插件包只有一个 `tailscale/` 根目录，普通文件与 `manifest.sha256` 一致，权限和平台标记正确。
- 通用包和对应平台包中的脚本、资源及同架构 payload 字节一致。
- 包内核心与签名描述符的大小、哈希和 ELF 架构一致，两个架构使用相同版本、源码提交和配方。
- 安装脚本完整文本满足软件中心的保护规则，包括注释内容。
- 相同输入及元数据的重复打包结果一致；重新生成签名封装时使用原 `created_at`。
- 发布后下载资源，复核文件名、大小和同批校验清单；核心稳定源只能指向已验证的不可变资源。

归档和安全相关回归测试位于 [test_packaging.py](../tests/test_packaging.py)、[test_pack_release.py](../tests/test_pack_release.py) 及 [辅助程序测试](../cmd/tsks-helper/security_test.go)。

## 设备与固件验证

容器测试可验证脚本控制逻辑和程序的 Linux 用户态行为。路由器固件的 TUN、内核 ABI、iptables 模块、软件中心实现、Fullcone 共存及真实路由转发需要在相应固件上验证。安装器的平台映射和 Linux 版本检查不能代替这些兼容性检查。

使用具备独立管理路径的测试设备，记录固件与软件中心版本、平台、内核、插件和核心版本，以及测试所用网络拓扑。按使用场景覆盖以下行为：

| 范围 | 检查内容 |
| --- | --- |
| 安装与迁移 | 全新安装、已有插件升级、通用包与平台包；确认只安装所需架构，并保留迁移前配置、核心和身份。 |
| 授权与停用 | 首次登录、设备审批、启用与关闭；等待授权和明确停用时不应被自动恢复反复启动。 |
| 基本连接 | 节点互访、路由器管理访问；区分直连和中继，以及控制连接状态。 |
| 路由与出口 | 本地 LAN 到远端子网、远端到本地 LAN、出口节点流量；验证控制台审批和访问规则。 |
| 协议设置 | 验证 IPv4/IPv6 选项影响外层 UDP 41641；同时记录 DERP 等连接路径。 |
| 网络重建 | 服务重启、WAN 重连、NAT 重建和地址变化后规则不重复增长，现有 Fullcone 钩子顺序保留。 |
| 核心管理 | 检查、更新和手动回退后实际版本正确，身份与配置继续可用。 |
| 失败恢复 | 在隔离测试环境模拟下载失败、资源不足和更新中断，检查原核心或恢复记录的保留情况。 |
| 自动恢复 | 持续故障满足条件时尝试恢复，并遵守冷却时间及滚动窗口限额；WAN 故障与授权等待不应误触发。 |
| 卸载与重装 | 插件文件及服务移除，身份文件保留；重新安装后检查设置及连接。 |

持续运行测试的时长应由固件变更、网络复杂度和使用场景决定。观察连接健康、资源占用、恢复尝试及规则数量，并覆盖正常业务流量和典型网络波动。

## 问题记录

出现异常时，先保留页面状态、任务日志和「生成诊断摘要」中的相关内容，再执行会改变现场的恢复操作。问题记录应包含：

- 预期行为、实际行为和可复现的操作步骤。
- 固件、软件中心、插件和核心版本。
- 发生时间、持续时间、WAN 状态及相关拓扑。
- 健康提示、恢复尝试记录和诊断片段。
- 自动化测试所用提交与命令；涉及发布文件时附同批校验值。

将测试日志与具体提交和环境关联，在问题记录中说明尚未覆盖的条件，便于复现与后续验证。公开提交诊断片段前，检查其中的设备名称、网络地址等内容。
