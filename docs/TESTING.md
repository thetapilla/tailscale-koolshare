# 测试指南

本文说明怎样重复验证插件，以及各项测试覆盖什么。构建依赖和产物目录见[构建与发布](BUILD.md)，日常排障见[使用指南](USER-GUIDE.md#常见问题)。

## 自动化检查

在仓库根目录执行。先按[构建与发布](BUILD.md)准备好需要的辅助程序、核心产物或正式安装包。

| 命令 | 验证范围 |
| --- | --- |
| `python3 -m unittest discover -s tests -p 'test_*.py' -v` | 后台生命周期、配置和防火墙；安装迁移；更新事务；打包与发布逻辑 |
| `node tests/test_ui.js` | 配置草稿与统一应用、生命周期进度、失败恢复、异步请求、超时、任务关联、轮询及文本渲染 |
| `python3 tools/test_helper.py` | Linux 上的签名与哈希、归档路径和文件类型、架构、LocalAPI、超时、原子链接及日志脱敏 |
| `python3 tools/test_busybox.py` | BusyBox 1.25.1 ash 的脚本语法，以及后台、安装、核心更新的回归测试；安装测试使用受限的 applet 命令目录 |
| `python3 tools/smoke_core.py` | 两种目标架构的真实压缩程序、daemon、辅助程序及 LocalAPI 冒烟测试 |
| `python3 tools/smoke_core_update.py --previous-release /path/to/previous-release` | 两种架构的已签名真实核心之间：服务启用时更新、手动回退、停用时更新及之后的启动 |
| `python3 tools/smoke_install.py --lifecycle` | 六份正式安装包的安装、重装、迁移及平台一致性；真实 ARM 核心、辅助程序、签名、userspace 服务启动与页面任务写入 |

### 回归测试覆盖的场景

- **构建依赖**：上游 Go 要求提高、精确版本选择、工具链和源码缓存损坏、发布锁的签名绑定、跨阶段输入一致，以及辅助程序独立构建。测试在 `test_toolchain.py`、`test_core_lock.py`、`test_helper_toolchain.py` 和打包发布测试中。
- **DNS 与自定义网段**：IPv4/IPv6 CIDR 边界及与保留范围的重叠、单条 TSV 错误、UTF-8/base64url 传输、十位提交与七位和九位的兼容、受理前拒绝、全部设置回滚、修复无效的存量数据、关闭时保留列表、与 LAN 合并去重，以及 DNS 双向切换。真实核心检查比较 `CorpDNS` 和 `AdvertiseRoutes`，并确认设备身份、主机名、连接意图和核心更新回退行为保持不变。
- **应用连接器**：
  - 后台：当前宣告列表与学习记录的交集、Control 前缀、顺序与掩码归一、出口默认条目不一致、开启和关闭、无关设置不写入路由参数、新键迁移和失败恢复。
  - 辅助程序：通过假的 Unix LocalAPI 和本机 DoH，测试标签匹配、A/AAAA 查询、地址校验、拒绝与超时、学习轮询，以及关闭时的读取次数。
  - 真实双架构核心：检查连接器偏好、学习接口和无关设置的 `EditPrefs` 日志；用随机生成身份的持久化学习记录，验证重启后保留，以及重复的自定义条目归谁负责。
  - 前端：缺少标签、未分配应用、学习结果、读取错误和旧草稿迁移。
- **开机与防火墙维护**：
  - 固件发起的启动在锁被占用时等待，页面请求立即返回；等待超时、执行失败和核心事务未能恢复时写入系统日志。
  - NAT 事件之后 filter 或 nat 表被整表替换时，重新应用插件规则；还没有 Tailscale 地址时同样处理。
  - daemon 规则丢失时，按后端状态和 WAN 状态决定是否重启；连续重启的上限与清零，包括推迟后补做的 NAT 事件；计数无法记录时不重启；NAT 事件本身不重启服务；规则列表读取失败时不当作规则缺失。
  - 测试替身的 `iptables -S` 默认输出 daemon 规则的三个跳转，用例按表移除它们来模拟固件重建。
- **下载镜像**：
  - 辅助程序：地址映射，以及对主机、路径和重定向的限制；发布地址返回错误、内容过大、中途断开、停滞或超时后改用镜像；第一个来源成功时不访问镜像；全部失败时不留下文件。
  - 更新脚本：改用镜像和全部失败时写入日志。
  - 镜像同步工具：先传归档、后传清单；跳过已有的文件；拒绝与签名清单不符的归档；没有配置凭据时跳过；请求签名与 AWS 文档的参考值一致。
- **软件中心标识**：全新安装登记的模块名、作者和文件名；从旧模块名升级时移除旧登记和旧文件；升级失败时原样恢复；卸载后不留登记。
- **核心保留与清理**：默认保留，并删除没有指针指向的核心；不保留时，提交后删除全部旧核心；更新失败或保留选择没能保存时不删除；参数先于任务校验；手动清理；当前核心损坏时拒绝清理；事务未完成或未持锁时拒绝删除；不跟随符号链接；空间不足时的删除顺序。
- **首次连接**：受限的 LocalAPI 请求只修改运行意图，设置和未托管的偏好完整保留；以真实的 `up` 作反向对照，复现旧版的偏好覆盖。文件状态只有 `{}` 时，再次启动仍应用 DNS 默认值。核心功能检查包括更新命令已移除、拒绝开启内置自动更新，以及持久化 `Apply=true` 时单次设置迁移成功。测试用的状态生成器在 `tools/testdata/mkstate/`，由 `build_core_fixture.py` 按核心依赖锁离线编译，随机密钥只留在隔离的测试目录里。

### 测试环境

- **脚本测试**：可写路径放在临时目录，用模拟命令代替固件服务、配置和防火墙操作。发布逻辑测试模拟 GitHub 操作。
- **BusyBox 测试**：测试工具先校验官方源码归档，再构建兼容环境，版本和校验值固定在[测试脚本](../tools/test_busybox.py)里。回归测试只允许显式列出的命令，禁用 `command` 内置命令，也不提供 `od`、`mkfifo`、`mktemp`、`sha256sum` 和外部 `timeout`：安装清单与核心校验、日志管道、临时文件和命令超时都由随包的辅助程序处理。防火墙测试覆盖不支持和支持等待参数的两种 iptables。
- **安装包冒烟测试**：从 `dist/` 解包，执行包内原始的安装器和运行库，用真实的签名、辅助程序和核心校验安装结果。平台信息、软件中心配置、空间、防火墙和定时任务使用模拟环境；检查安装一致性时服务保持停用。`--lifecycle` 另外启用 userspace daemon，验证日志管道、LocalAPI、设置应用和页面任务文件，不需要 TUN，也不加入 Tailnet。它使用容器的 Shell，与 BusyBox 回归测试覆盖的是不同的边界。
- **真实核心冒烟测试**：使用原生架构或 QEMU，在没有网络的临时容器中运行，覆盖 userspace daemon、未登录状态和随机生成的合成已登录身份，不需要加入 Tailnet。辅助程序与事务的单元测试还覆盖带源码提交后缀的版本、错误的源码、未知的版本后缀、本地接口短暂不可用、已授权身份丢失和控制面尚未同步的状态。

## 真实核心更新事务

准备两个不同版本或构建号的不可变核心 Release。每个目录都要有原 `manifest.json` 和清单列出的 ARM32、ARM64 归档；候选核心的版本与构建号组合必须高于旧核心。构建辅助程序后运行：

```sh
python3 tools/smoke_core_update.py \
  --previous-release /path/to/previous-release \
  --candidate-release build/core-release
```

默认依次测试 ARM64 和 ARM32，也可以用 `--arch arm` 或 `--arch arm64` 单独运行。测试容器没有外部网络，根文件系统只读，可写状态放在临时内存目录；输入的核心和源码都以只读方式挂载。辅助程序实际验证签名并解包，用原有的更新事务函数、真实的 combined 核心和 LocalAPI 执行以下路径：

- 服务启用时切换到新核心，核对实际的短版本和带构建后缀的完整版本，并确认运行意图和临时生成的机器身份保留下来。
- 服务启用时手动回退，验证上一核心能够启动并通过自检。
- 停用服务后更新，确认更新不会启动 daemon，也不修改已停止的 state；之后手动启动并再次验证。
- 每次成功切换后，确认当前和上一核心的指针正确，事务记录和本次快照已清理。

测试要求 daemon 真实返回带构建后缀的完整版本，并与原始的 CLI JSON 对照，避免用清单里的短版本代替真实响应、漏掉格式差异。DBus、NVRAM、防火墙和定时任务由测试替身提供；只有 daemon 入口加了 userspace TUN 参数。测试使用随机合成的已登录身份，保留旧的 `AutoUpdate.Apply=true` 来验证迁移，并比较设备密钥和未托管的偏好。加上 `--legacy-plugin-root /path/to/old-plugin`，可以验证旧插件遇到不兼容的候选核心时能安全回退。合成身份不接入 Tailnet；实际审批、硬件 TUN、防火墙和流量转发由设备检查覆盖。

完整的事务测试还包含安装回滚时不应用偏好的启动路径，也可以用 `--restore-only` 单独运行：新 DBus 中 DNS 默认关闭、已恢复的 profile 中 DNS 开启、且连接意图为停用时，确认直接启动和就绪检查不修改偏好、身份或登录状态。这条路径不调用 `tailscale set` 或 `connect`；正常启动仍按页面配置应用 DNS 和网段。

## 固件组件与浏览器集成

对本地固件镜像执行以下命令，可以在隔离容器中提取并运行它原始的 BusyBox、Shell 和工具集。原镜像保持只读；报告按镜像 SHA-256 保存到 `build/firmware-compat/`，包含每组测试前后的源码哈希。`--export-runtime` 同时导出接口测试所需的最小运行目录。

```sh
python3 tools/firmware_compat.py --build-image --export-runtime /path/to/firmware.pkgtb
python3 tools/smoke_httpdb.py --firmware-root /path/to/runtime-root
```

加上 `--params-only` 可以单独验证空列表、IPv4/IPv6、32 条最长合法输入、Unicode 和过长请求。传输使用带 `b64.` 前缀的 base64url；完整的接口测试还验证新配置确实写入 DBus、七位和九位提交保留新增的键，以及无效列表不创建任务、不写配置。

接口测试运行固件里的 httpdb、skipd、DBus 客户端和 Shell，并执行实际的辅助程序，覆盖请求 ID 边界、回复编码、状态与接口查询、设置、任务回执、操作锁、错误结果和失效任务的恢复。NVRAM、网络、防火墙、外网下载和 LocalAPI 数据使用固定的测试输入。

浏览器测试需要 Node.js、Playwright 和兼容的 Chromium。先在回环地址上启动隔离的接口服务，等它输出 `HTTPDB_READY`（初始化期间会执行配置和操作锁测试），再在另一个终端运行浏览器检查：

```sh
python3 tools/smoke_httpdb.py --firmware-root /path/to/runtime-root --serve --port 33030
node tools/smoke_ui.js --firmware-root /path/to/runtime-root --upstream http://127.0.0.1:33030
```

浏览器命令的 `--firmware-root` 需要包含完整的 `www/` 样式、图片和软件中心资源；只导出了 Shell/httpdb 的最小运行目录不能作为网页资源的输入。可以让 httpdb 使用最小运行目录，浏览器使用同一固件完整解压后的根目录。缺少页面必需的样式时，浏览器检查会立即失败。

浏览器加载固件自带的 jQuery、软件中心资源和插件的原始页面，覆盖初始显示、保存设置、诊断、核心检查、异常响应后的恢复，以及刷新页面后的任务跟踪。额外的生命周期场景由本地代理注入延迟的 HTTP 响应，检查启用开关只修改草稿、应用后的启动和停止进度，以及失败后恢复草稿和错误提示。这部分只验证浏览器交互，实际的核心切换由上面的真实核心事务测试覆盖。路由器导航和硬件相关的模板值使用测试替身。`--chromium` 可以指定已有的浏览器；Playwright 可以通过 `NODE_PATH` 使用已有的安装。

打包后，给上面两个工具都加上 `--plugin-root build/packages/universal/tailscaleks`，可以检查归档暂存区里实际的页面、脚本、缓存标识和辅助程序。截图保存在 `build/ui-smoke/`，内容是隔离的测试数据；完整的固件启动、硬件网络和流量转发仍按下文的设备检查执行。固件和提取出的资源只作为本地测试输入，不随源码和插件 Release 分发。

## 发布产物检查

完成核心准备和插件打包后，检查同一批安装包和核心元数据：

- 六个标准插件包和 `SHA256SUMS` 齐全，文件名和包内版本与 [VERSION](../VERSION) 一致。
- 每个插件包只有一个 `tailscaleks/` 根目录，普通文件与 `manifest.sha256` 一致，权限和平台标记正确。
- 通用包和对应平台包中的脚本、资源及同架构 payload 逐字节一致。
- 包内核心与 `bundled_core.json` 的版本、构建号一致，符合原签名描述符的大小、哈希和 ELF 架构；两种架构使用相同的源码提交和配方。
- 安装脚本的完整文本（包括注释）满足软件中心的保护规则。
- 相同输入和元数据重复打包的结果一致；导入预装核心时保留原签名清单的字节。
- 发布后下载资源，复核文件名、大小和同批校验清单；核心稳定源只能指向已验证的不可变资源。

归档和安全相关的回归测试在 [test_packaging.py](../tests/test_packaging.py)、[test_pack_release.py](../tests/test_pack_release.py) 和[辅助程序测试](../cmd/tsks-helper/security_test.go)中。

## 设备与固件验证

容器测试能验证脚本的控制逻辑和程序在 Linux 用户态的行为。路由器固件的 TUN、内核 ABI、iptables 模块、软件中心实现、与 Fullcone 共存以及真实的路由转发，需要在相应的固件上验证。安装器的平台映射和 Linux 版本检查不能代替这些兼容性检查。

使用有独立管理途径的测试设备，记录固件和软件中心版本、平台、内核、插件和核心版本，以及测试用的网络拓扑。按使用场景覆盖以下行为：

| 范围 | 检查内容 |
| --- | --- |
| 安装与迁移 | 全新安装、已有插件升级、通用包与平台包；确认只安装所需的架构，并保留迁移前的配置、核心和身份。 |
| 授权与停用 | 首次登录、设备审批、启用与关闭；等待授权和明确停用时，不应被自动恢复反复启动。 |
| 基本连接 | 节点互访、访问路由器的管理入口；区分直连和中继，以及控制连接的状态。 |
| 路由与出口 | 本地 LAN 到远端子网、远端到本地 LAN、出口节点流量；验证控制台审批和访问规则。 |
| 协议设置 | 验证 IPv4/IPv6 选项影响外层的 UDP 41641，同时记录 DERP 等连接路径。 |
| 网络重建 | 服务重启、WAN 重连、NAT 重建和地址变化后，规则不重复增长，已有的 Fullcone 钩子顺序保持不变。 |
| 应用连接器 | 升级前后比较学习记录与宣告列表；应用无关设置不写入 `AdvertiseRoutes`，移除与学习记录重叠的自定义条目不撤下地址；改变 LAN 后保留连接器条目并恢复学习。检查关闭和开启、自查、客户端 DNS、批准和实际转发。 |
| 核心管理 | 检查、更新和手动回退后实际版本正确，身份与配置继续可用。 |
| 失败恢复 | 在隔离的测试环境中模拟下载失败、资源不足和更新中断，检查原核心或恢复记录是否保留。 |
| 自动恢复 | 持续故障满足条件时尝试恢复，并遵守冷却时间和滚动窗口内的次数上限；WAN 故障和等待授权不应误触发。 |
| 卸载与重装 | 插件文件和服务被移除，身份文件保留；重新安装后检查设置和连接。 |

长时间运行测试的时长，按固件改动、网络复杂度和使用场景决定。观察连接健康、资源占用、恢复尝试和规则数量，并覆盖正常的业务流量和典型的网络波动。

## 问题记录

出现异常时，先保留页面状态、任务日志和「生成诊断摘要」的相关内容，再执行会改变现场的恢复操作。问题记录应包含：

- 预期行为、实际行为和可以复现的操作步骤。
- 固件、软件中心、插件和核心的版本。
- 发生时间、持续时间、WAN 状态和相关的网络拓扑。
- 健康提示、恢复尝试记录和诊断片段。
- 自动化测试所用的提交和命令；涉及发布文件时，附上同批的校验值。

把测试日志与具体的提交和环境对应起来，并在问题记录中写明尚未覆盖的条件，方便复现和后续验证。公开提交诊断片段前，检查其中的设备名称、网络地址等信息。
