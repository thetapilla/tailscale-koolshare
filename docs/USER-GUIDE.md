# 使用指南

## 安装要求

插件面向提供 Koolshare 软件中心的 ARM 固件，支持的平台与安装包见 [README](../README.md#下载与安装)。平台名称遵循软件中心的分类，不应仅凭路由器处理器位数选择安装包。通用包按安装器的平台映射自动选择架构。

固件需要 Linux 4.1 或更新内核，以及可用的 TUN、iptables、软件中心服务和命令工具。IPv6 传输规则还依赖固件提供 ip6tables。不同固件的内核功能和防火墙实现可能存在差异；验证方法见 [测试指南](TESTING.md#设备与固件验证)。

安装需要至少 32 MiB 可用内存，以及容纳新文件、安装暂存和备份的持久存储空间；安装器另保留 8 MiB 存储余量。选择平台包可减少下载和上传所需空间，最终安装内容与通用包选择相同架构时一致。

## 安装与首次登录

1. 从 [最新插件 Release](https://github.com/thetapilla/tailscale-koolshare/releases/latest) 下载对应的 `tailscale_<版本>_<平台>.tar.gz`，需要核对下载完整性时使用同批 `SHA256SUMS`。
2. 在软件中心的「离线安装」页面上传安装包，等待安装完成。
3. 打开 Tailscale 插件页面，勾选「启用 Tailscale」并点击「应用设置」。尚未登录的设备会显示「登录并授权」链接。
4. 完成 Tailscale 登录；如果 Tailnet 开启了设备审批，在管理控制台批准设备后再检查连接状态。

安装和应用设置会短暂中断 Tailscale 连接。远程维护时应保留另一条路由器管理路径。

升级插件会保留已有配置、设备身份和已安装核心，包括支持迁移的原版 combined 核心。全新安装使用安装包附带的核心。页面中的「当前核心」显示运行中的版本，服务停用时显示已安装版本；升级插件后可以单独检查核心更新。

## 网络设置

启用开关与其他选项共同组成待应用的设置。调整后点击「应用设置」统一保存并生效；应用期间请等待操作结果。失败后，页面保留待应用的设置供检查和重试。

| 选项 | 作用 |
| --- | --- |
| 直连协议：IPv4 / IPv6 | 允许相应地址族的 Tailscale 外层 UDP 传输。关闭后通过防火墙阻断该地址族的 UDP 41641 收发；这不等同于关闭 Tailnet 内部的 IPv4/IPv6 地址，连接也可能使用 DERP 中继。 |
| 共享本地局域网 | 将路由器当前 LAN 的 IPv4 网段宣告给 Tailnet。需要在 Tailscale 控制台批准路由，并配置适用的访问规则。 |
| 访问远程局域网 | 接受其他节点宣告的子网路由。各地 LAN 宜使用不同网段，避免与本地或上级路由器宣告的网段冲突。 |
| 使用 Tailscale DNS | 默认关闭。开启后，路由器自身使用 Tailnet 的 DNS 设置，可解析 Tailnet 设备名；局域网设备继续遵循固件的 DNS 配置。 |
| 提供互联网出口 | 将此路由器宣告为出口节点。需要在控制台批准，并在需要使用出口的客户端选择该节点。 |
| 提供应用连接器 | 按管理控制台分配的域名学习目标地址，并向 Tailnet 宣告。页面显示本机分配及学习状态；标签、应用和自动批准在控制台配置。 |
| 自动恢复连接 | 对持续的本地服务故障或符合条件的控制连接故障尝试重启插件服务。 |

Tailscale 控制台中的设备审批、路由批准和访问规则仍决定可达范围。协议细节可查阅官方 [子网路由器说明](https://tailscale.com/docs/features/subnet-routers) 和 [出口节点说明](https://tailscale.com/docs/features/exit-nodes)。

每次启动都会按「使用 Tailscale DNS」开关应用 DNS 偏好；在命令行临时修改后，下一次应用设置或启动仍以页面开关为准。插件未托管的其他偏好保持不变。

## 自定义共享网段

在「共享本地局域网」一行勾选「高级：自定义网段」，逐条填写 IPv4 或 IPv6 CIDR，再点击「应用设置」。支持最多 32 条，可用 `/32` 或 `/128` 宣告单个地址。关闭高级开关会停止由该列表提供的宣告并保留列表；同时由应用连接器负责的地址会继续宣告。

该开关与局域网共享独立：可只宣告自定义地址，也可与本机 LAN 网段合并。重复条目会去重；包含主机位的输入会提示应使用的网络地址，需确认后自行修改。默认路由请使用「提供互联网出口」；Tailscale 地址空间、环回、组播、链路本地、未指定地址及 IPv4 映射 IPv6 网段不接受为自定义网段。

每条路由都需在管理控制台批准，并满足 Tailnet 的访问规则。页面显示实际已宣告网段及控制面选定的本机主路由；没有列为主路由不一定代表尚未批准，也可能处于备用状态。批准状态请在管理控制台查看。

多台路由器的 LAN 网段相同时，不要同时共享该 LAN。可以只启用各自需要的自定义网段，避免把独立局域网当成同一网络的备用路由。

## 应用连接器

应用连接器根据管理控制台分配的域名，观察经本机连接器 DNS 接口返回的地址，再向 Tailnet 宣告这些地址。页面的开关表示本机愿意提供连接器服务；实际负责哪些域名由控制台的 Apps 设置决定。参见 Tailscale 的[应用连接器说明](https://tailscale.com/docs/features/app-connectors)及[配置步骤](https://tailscale.com/docs/features/app-connectors/how-to/setup)。

### 经指定路由器访问软件中心

选择能够正常访问软件中心服务器的路由器作为连接器，在管理控制台完成以下设置：

1. 在访问策略的 `tagOwners` 中定义专用标签，例如 `tag:softcenter-connector`，指定有权分配它的管理员。专用标签只分配给预期的连接器设备。
2. 给所选路由器添加该标签，并检查设备的密钥过期设置；长期服务的连接器应关闭密钥过期，或部署高可用方案。密钥过期后，其他设备可能继续保留该连接器的转发条目，但流量无法通过。
3. 在 **Apps** 中创建应用，选择该专用标签，填写 `rogsoft.ddnsto.com` 和 `merlin.koolcenter.com`。应用域名在这里维护。
4. 为该标签配置 `autoApprovers.routes`，允许自动批准连接器新学习的 IPv4/IPv6 地址；同时按访问需求配置访问规则，允许客户端发现连接器并访问目标服务。自动批准与访问权限分别生效。

如果要让该专用标签自动批准任意新学到的 IPv4/IPv6 地址，可将以下片段合并到现有访问策略；仅给可信的连接器设备使用此标签：

```json
"autoApprovers": {
  "routes": {
    "0.0.0.0/0": ["tag:softcenter-connector"],
    "::/0": ["tag:softcenter-connector"]
  }
}
```

在连接器路由器的插件页面勾选「提供应用连接器」，点击「应用设置」。检查状态行显示的已分配域名与已学习地址；缺少标签、尚未分配应用或读取失败会显示相应提示。此功能与本机「使用 Tailscale DNS」独立，也可与互联网出口功能并用。

访问端需接受子网转发条目：路由器启用「访问远程局域网」，桌面客户端开启 Use Tailscale subnets。使用 Tailscale DNS 的客户端查询已分配域名时才会触发学习；客户端同时使用出口节点时，需 Tailscale 1.88.1 或更新版本（见[上游兼容说明](https://github.com/tailscale/tailscale/issues/16384)）。局域网中未安装 Tailscale 的设备，可经已接受这些条目的网关访问已经学到的地址。

在客户端查询域名，确认请求使用连接器的 DNS 接口：

```sh
tailscale dns query rogsoft.ddnsto.com
```

在连接器路由器上检查学习记录：

```sh
/koolshare/tailscale/current/tailscale --socket=/tmp/tailscale3/tailscaled.sock appc-routes --map
```

对查询结果中的目标 IP，Linux 使用 `ip route get <目标IP>`，macOS 使用 `route -n get <目标IP>` 检查实际路径。浏览器和路由器发起的是不同的连接，两者均需可用路径。随后刷新软件中心的列表与公告，并检查服务器响应：

```sh
curl --connect-timeout 5 --max-time 15 -sS -o /dev/null -w '%{http_code}\n' \
  'https://rogsoft.ddnsto.com/koolcenter/app.json.js'
```

### 学习与维护

插件在开启连接器或修改宣告列表后，尝试向本机连接器查询已分配的精确域名，帮助及时学习。访问控制拒绝自查、域名暂不可解析或学习尚未完成时，操作日志会提示，服务仍可启动；后续客户端查询可以继续触发学习。`*.` 通配域名需由客户端访问具体主机名后学习。

软件中心场景使用上述两个精确域名；`*.ddnsto.com` 还覆盖其他用户的 DDNSTO 隧道，不宜作为该应用的域名清单。核心可能保留曾经学到的旧地址，DNS 地址变化不会立即撤下全部旧条目。不同域名共用同一 IP 时，去往该 IP 的连接都会使用相同转发路径。迁移或删除应用前，应检查域名清单、宣告列表及控制台批准状态。

已宣告条目可能来自 LAN、自定义网段或连接器。自定义列表中的单地址与连接器学习结果重叠时，可以在确认连接器正常后移除该自定义条目；连接器会继续负责已加入宣告列表的地址。关闭连接器会按当前 LAN、自定义网段和出口设置重算宣告列表。

若不使用应用连接器，也可在「高级：自定义网段」中宣告当前服务器 IP 的 `/32`（IPv6 用 `/128`），在控制台批准，并让访问端接受子网条目。这是固定地址后备方案，服务器解析变化后需手动更新。

### 升级到 3.3.0

新增开关在首次启动时沿用核心当前值，随后由页面统一管理；服务停用且尚未读到核心当前值时，该选项暂不可编辑；先启用服务，再按需调整。宣告列表不变时，升级启动及无关设置应用保留连接器学习记录。调整宣告列表时，会保留仍由连接器负责的地址并尝试恢复学习记录；持久化学习记录还依赖控制面启用 `AppCStoreRoutes`。回退到 3.2.0 后，旧版本仍可能在应用设置或启动时清空学习记录。

## 核心更新与回退

1. 点击「检查更新」，读取本项目的签名稳定核心清单。
2. 有可用更新时点击「更新核心」，在操作区域查看进度与结果。
3. 更新后检查当前核心版本、连接状态和常用路由。
4. 需要恢复时，使用可用的「回退上一核心」按钮。

版本后面的 `(rN)` 是该上游版本的核心构建号，例如 `1.104.1 (r2)`。上游版本相同时，较大的构建号表示较新的构建配方。「原版核心」表示从原版插件迁移的程序。页面会显示回退目标；更新源与当前核心相同时，更新按钮禁用。

更新按设备架构下载核心，并验证 Ed25519 签名、SHA-256、版本、归档内容和 ELF 架构。更新需要至少 64 MiB 可用内存及新核心所需存储空间，另保留 8 MiB 持久存储余量。空间不足时可能清理缓存的上一核心；只有保留了可用上一核心时才提供手动回退。

核心切换会短暂中断连接。切换后会检查本地服务、实际版本和设备身份；检查失败时尝试恢复原核心及状态。若恢复未完成，页面会报告失败并保留恢复记录。后续启动或核心操作会先处理未完成事务；安装和卸载会提示先完成恢复，再重新操作。

核心更新不会自动安装。插件升级也不会用包内核心覆盖已有核心。安装包预装版本以 [预装核心配置](../tools/bundled_core.json) 为准，核心的源码、工具和功能选项见 [构建配方](../tools/core_recipe.json) 及对应核心 Release 的元数据。精简构建不包含 Tailscale SSH、Taildrop 等功能，路由器原有系统 SSH 服务由固件管理。

从核心构建 r2 起，Tailscale 自带的自动更新、远程更新及 `tailscale update` 已移除。请使用插件页面的签名核心更新通道，并先将插件升级到 3.1.0 或更新版本。插件每次启动会关闭核心内置自动更新及更新提示；升级插件后仍需在页面单独更新已有核心。

## 升级到 3.2.0

通过软件中心安装新版插件会保留设备身份、已有设置和已安装核心。新增的 DNS 开关默认关闭，服务下次启动时会关闭 Tailscale DNS，并由 Tailscale 还原固件的 DNS 配置。曾通过命令行启用 Tailscale DNS、希望继续使用的用户，需要在页面勾选新开关并应用。

自定义共享网段默认关闭且列表为空。升级时仍开着的旧页面可以提交原有设置，新选项的现有值会保留；重新打开页面后即可使用新选项。

## 状态与诊断

页面分别显示运行状态、Tailnet 连接、健康提示和接口流量。正在应用设置时，页面根据操作显示「正在启动」「正在停止」或「正在应用设置」；核心切换时显示「正在切换核心」。操作完成后重新读取当前状态。未知或暂时无法读取的状态不等于设备已经离线。

- 「连接详情」显示当前连接状态摘要。
- 「网络检查」检查本地服务、WAN、经 TLS 验证的控制端 HTTPS 可达性，以及有时间上限的 Tailscale 网络探测。
- 「生成诊断摘要」在操作区域显示实际核心版本、后端状态、健康信息、内存和存储概况，以及长度受限、经过凭据脱敏的近期运行日志。

诊断内容显示在页面的「操作日志」区域，可复制所需文本。诊断不会打包设备 state 文件、私钥或认证令牌。报告问题时附上固件与软件中心版本、插件及核心版本、复现步骤、相关健康提示和诊断片段。

如果页面暂时失去任务响应，使用「继续查询进度」检查原任务；若仅日志读取失败，使用「重新读取日志」。先确认操作结果，再决定是否重新发起操作。

任务记录已失效且后台确认没有操作正在运行时，页面会结束跟踪并重新读取设置和状态。此时结果显示为「任务结果无法确认」；核对当前设置后，再决定是否重试。

## 自动恢复

自动恢复默认开启。服务启用期间，维护任务每分钟运行；启动后的宽限期、连续失败确认、WAN 检查和恢复限额用于减少无效重启。两次自动恢复至少间隔 30 分钟，任意连续 24 小时内最多尝试两次。

等待登录或审批、明确停用及短时网络波动不会立即触发恢复。恢复只重启插件服务，保留设备身份和主动断开或登出的连接状态。授权后地址变化及 NAT 重建的规则维护独立于自动恢复开关运行。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 安装包与平台不匹配 | 按软件中心平台选择包，或使用通用包；查看安装日志中的平台识别结果。 |
| 提示内存或存储不足 | 按日志确认不足的资源。核心更新需要额外的暂存空间；清理无用文件后重新检查。 |
| 等待登录或设备审批 | 使用页面授权链接，并检查 Tailscale 控制台中的审批状态。 |
| 服务运行，但子网或出口不可达 | 检查路由批准、Tailnet 访问规则、客户端出口选择、网段冲突及固件转发规则。 |
| 核心检查或下载失败 | 检查系统时间、DNS、HTTPS 连通性及 GitHub 发布文件的可达性；保留任务日志中的具体错误。 |
| 提示另一个操作正在进行 | 等待当前任务完成，再查询状态。生命周期、安装、核心操作和诊断共用操作锁。 |
| 页面提示读取失败或超时 | 页面会自动重试。若持续失败，重新打开插件页并确认路由器管理会话有效；记录提示内容和固件、插件版本以便排查。 |
| 提示需要恢复核心事务 | 保留任务日志，通过启动或核心操作重试恢复；不要手工删除恢复记录后继续安装。 |
| 连接持续异常 | 在重启前记录健康提示和诊断日志，检查 WAN、资源与固件网络配置；参阅 [测试指南](TESTING.md)。 |

## 卸载

从软件中心卸载会停止服务并移除插件程序和核心缓存。设备身份文件保留在 `/koolshare/configs/tailscale`，重新安装后可继续使用。软件中心可能清理插件设置，重新安装后请检查网络和自动恢复选项。
