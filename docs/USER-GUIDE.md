# 使用指南

这份指南介绍插件的安装、设置和日常维护。各版本的改动和升级注意事项见[更新记录](../CHANGELOG.md)。

文中几个说法的含义：

| 说法 | 含义 |
| --- | --- |
| 核心 | 路由器上运行的 Tailscale 程序（`tailscale` 和 `tailscaled`）。插件和核心分开更新。 |
| 管理控制台 | Tailscale 的网页后台（[login.tailscale.com/admin](https://login.tailscale.com/admin)），用来批准设备和路由、编写访问规则。 |
| 宣告 | 路由器向 Tailnet 声明某些网段可以经它访问。宣告的网段经管理控制台批准（手动或自动）后才生效。 |
| 设备身份 | 路由器在 Tailnet 中的登录状态和密钥，保存在 `/koolshare/configs/tailscale`。身份保留下来，重装插件后路由器仍是 Tailnet 里原来那台设备。 |

## 安装

### 安装前确认

- **固件**：带 Koolshare 软件中心，Linux 内核 4.1 或更新，提供 TUN 和 iptables；IPv6 相关的防火墙规则还需要 ip6tables。不同固件的内核功能和防火墙实现可能有差异，验证方法见[测试指南](TESTING.md#设备与固件验证)。
- **内存**：至少 32 MiB 可用内存。
- **存储**：JFFS 要有足够的剩余空间。安装器要放下新文件和安装期间的备份，另外留出 8 MiB 余量；软件中心第一次安装某个插件时，还要求剩余空间不小于安装包解压后的大小加 2 MB。

以 3.4.0 为例，JFFS 大约需要这么多剩余空间：

| 情况 | 平台安装包 | 通用安装包 |
| --- | --- | --- |
| 全新安装 | 17 MB | 19 MB |
| 从插件市场原版迁移 | 22 MB | 22 MB |

空间不够时，安装会在替换任何文件之前停止，已有的插件和设置不受影响。升级本插件需要的空间见[更新记录](../CHANGELOG.md)中对应版本的升级说明。

### 选择安装包

从 [Releases](https://github.com/thetapilla/tailscale-koolshare/releases/latest) 下载与机型对应的安装包，对应关系见 [README](../README.md#选择安装包)。拿不准就用通用包（`_universal`），它包含两种架构，安装时按机型自动选择。

文件名格式为 `tailscaleks_<版本>_<平台>.tar.gz`，上传前不要改名。需要核对下载是否完整时，用同一 Release 中的 `SHA256SUMS`。

### 安装并登录

1. 在软件中心的「离线安装」页面上传安装包，等待安装完成。
2. 打开 Tailscale 插件页面，勾选「启用 Tailscale」，点「应用设置」。
3. 还没登录过的路由器会显示「登录并授权」链接，点开后登录 Tailscale 账号。
4. 如果 Tailnet 开启了设备审批，到管理控制台批准这台路由器，再回到插件页面查看连接状态。

安装和「应用设置」都会让 Tailscale 短暂断开。如果你正通过 Tailscale 远程管理这台路由器，请先准备另一条能连上路由器的途径。

### 升级插件

下载新版安装包，同样在「离线安装」页面上传，不需要先卸载。升级保留设置、设备身份和已安装的核心；安装包附带的核心只在全新安装时使用，已有的核心要在插件页面单独更新。

安装中途出错时，安装器会还原安装前的文件、设置和设备身份；原来处于启用状态的，会重新启动原来的服务。还原也没有全部完成时，安装备份会保留在路由器上，安装日志会给出位置。

个别版本升级时有额外的注意事项，写在[更新记录](../CHANGELOG.md)对应版本的「升级说明」里，升级前请先看一下。

### 从插件市场原版迁移

插件市场里的 Tailscale 插件（作者 sadog，模块名 `tailscale`，下文称原版）是本插件的来源。本插件的模块名是 `tailscaleks`，两者在软件中心里是两个不同的插件，但共用设置和文件位置，不能同时安装。

已经装了原版的路由器，直接离线安装本插件即可，不用先卸载原版。安装时：

- 停止原版的 Tailscale 服务。
- 保留设备身份，路由器在 Tailnet 中仍是原来那台设备。
- 沿用原版的设置：是否启用、直连协议、共享本地局域网、访问远程局域网和提供互联网出口。原版没有的选项取默认值：「使用 Tailscale DNS」关闭，「自动恢复连接」开启，自定义网段关闭。
- 继续使用原版的核心，插件页面在版本号后标注「原版核心」。
- 替换原版的脚本，移除它在软件中心的登记、页面、图标和卸载脚本。之后插件市场会把原版显示为「未安装」。

装好后：

1. 打开插件页面核对各项设置。本插件默认不让路由器使用 Tailscale DNS；原版上用过的话，勾选「使用 Tailscale DNS」后点「应用设置」。
2. 在「核心管理」中点「检查更新」和「更新核心」，换成本项目构建并签名的核心。勾选了「更新时保留旧核心」时，原版核心会留作回退目标。

迁移比全新安装需要更多空间（见[安装前确认](#安装前确认)）。空间不够时，也可以先在软件中心卸载原版，再全新安装本插件：原版卸载时保留 `/koolshare/configs/tailscale`，设备身份不会丢；但软件中心会一并清除插件设置，装好后要重新启用并设置。

想换回原版时，先在软件中心卸载本插件（设备身份和设置都会保留），再从插件市场安装原版。不要在本插件还装着时安装原版：原版的文件与本插件同名，会直接覆盖本插件。

## 网络设置

勾选或取消选项只修改页面上的草稿，点「应用设置」后才保存并生效。应用期间请等待结果；应用失败时，页面保留你改过的设置，方便检查后重试。

| 选项 | 作用 |
| --- | --- |
| 直连协议：IPv4 / IPv6 | 允许 Tailscale 用 IPv4 或 IPv6 收发外层 UDP 数据。取消勾选后，插件用防火墙阻断该协议的 UDP 41641 收发，连接可能改用 DERP 中继。它不会关闭 Tailnet 内部的 IPv4 或 IPv6 地址。 |
| 共享本地局域网 | 把路由器 LAN 的 IPv4 网段宣告给 Tailnet。还需要在管理控制台批准这条路由，并配好访问规则。 |
| 访问远程局域网 | 接受其他设备宣告的子网。各处 LAN 最好使用不同网段，避免与本地或上级路由器的网段冲突。 |
| 使用 Tailscale DNS | 默认关闭。开启后，路由器自身的域名解析经过 Tailscale，可以解析 Tailnet 设备名；局域网设备仍按固件的 DNS 设置解析。 |
| 提供互联网出口 | 把这台路由器宣告为出口节点。需要在管理控制台批准，再在要使用出口的设备上选择它。 |
| 提供应用连接器 | 让 Tailnet 中的设备按域名经这台路由器访问指定网站。见下文[应用连接器](#应用连接器)。 |
| 自动恢复连接 | 本地服务持续故障，或控制连接故障符合条件时，尝试重启插件服务。见下文[自动恢复](#自动恢复)。 |

最终能访问哪些设备和网段，由管理控制台里的设备审批、路由批准和访问规则决定。原理可参考 Tailscale 官方的[子网路由器说明](https://tailscale.com/docs/features/subnet-routers)和[出口节点说明](https://tailscale.com/docs/features/exit-nodes)。

插件每次启动都按「使用 Tailscale DNS」的勾选设置 DNS。用命令行临时改过的 DNS 设置，会在下次应用设置或启动时被页面设置覆盖；插件不管理的其他 Tailscale 设置保持不变。

### 自定义共享网段

在「共享本地局域网」一行勾选「高级：自定义网段」，逐条填写 IPv4 或 IPv6 CIDR，再点「应用设置」。最多 32 条，单个地址可以用 `/32` 或 `/128` 宣告。

- 自定义网段和局域网共享分开启用：可以只宣告自定义网段，也可以与本机 LAN 网段一起宣告。
- 关闭「高级：自定义网段」会停止宣告列表中的网段，但保留列表；其中仍由局域网共享或应用连接器负责的条目会继续宣告。
- 重复的条目会自动去重。输入带主机位时（例如 `192.168.1.5/24`），页面会提示正确的网络地址，请确认后自行修改。
- 默认路由请用「提供互联网出口」。Tailscale 地址空间、环回、组播、链路本地、未指定地址和 IPv4 映射的 IPv6 网段不能作为自定义网段。

每条网段都要在管理控制台批准，并符合 Tailnet 的访问规则。页面会显示实际已宣告的网段，以及控制面选定由本机承担的主路由。某个网段没有列为主路由，不一定是还没批准，也可能处于备用状态；批准状态请在管理控制台查看。

多台路由器的 LAN 网段相同时，不要同时共享这个 LAN。可以只启用各自需要的自定义网段，免得把两个独立的局域网当成同一网络的备用路由。

### 应用连接器

应用连接器让 Tailnet 中的设备按域名经这台路由器访问指定网站。管理控制台把域名分配给本机后，Tailnet 中的设备通过本机查询这些域名时，本机记下解析出的地址，再把这些地址宣告给 Tailnet。页面上的开关只表示本机愿意担任连接器；具体负责哪些域名，由管理控制台的 Apps 设置决定。参见 Tailscale 的[应用连接器说明](https://tailscale.com/docs/features/app-connectors)和[配置步骤](https://tailscale.com/docs/features/app-connectors/how-to/setup)。

插件第一次启动服务前读不到核心当前的连接器设置，这时「提供应用连接器」暂时不能修改，应用设置会保留原值；启用服务后即可调整。

#### 示例：经指定路由器访问软件中心

选一台能正常访问软件中心服务器的路由器担任连接器，然后在管理控制台完成以下设置：

1. 在访问策略的 `tagOwners` 中定义一个专用标签，例如 `tag:softcenter-connector`，并指定谁有权分配它。这个标签只分配给预期的连接器设备。
2. 给这台路由器加上该标签，并检查设备的密钥过期设置：长期运行的连接器应关闭密钥过期，或者部署高可用方案。密钥过期后，其他设备可能仍保留经这台连接器的转发条目，但流量过不去。
3. 在 **Apps** 中创建应用，选择这个标签，填写 `rogsoft.ddnsto.com` 和 `merlin.koolcenter.com`。以后增删域名也在这里改。
4. 为这个标签配置 `autoApprovers.routes`，让连接器新学到的 IPv4/IPv6 地址自动获批；同时配置访问规则，允许客户端发现连接器并访问目标服务。自动批准和访问权限是分开生效的。

要让这个标签自动批准任意新学到的 IPv4/IPv6 地址，可以把下面的片段合并到现有访问策略。只把这个标签给可信的连接器设备：

```json
"autoApprovers": {
  "routes": {
    "0.0.0.0/0": ["tag:softcenter-connector"],
    "::/0": ["tag:softcenter-connector"]
  }
}
```

在这台路由器的插件页面勾选「提供应用连接器」，点「应用设置」，然后查看状态行里的已分配域名和已学习地址。缺少标签、还没分配应用或读取失败时，页面会给出对应提示。这个功能与本机的「使用 Tailscale DNS」互不影响，也可以和互联网出口同时使用。

访问端要接受子网的转发条目：路由器勾选「访问远程局域网」，桌面客户端开启 Use Tailscale subnets。客户端需要使用 Tailscale DNS，它查询已分配的域名时会触发学习；客户端同时使用出口节点时，需要 Tailscale 1.88.1 或更新版本（见[上游兼容说明](https://github.com/tailscale/tailscale/issues/16384)）。局域网里没装 Tailscale 的设备，可以经已经接受这些条目的网关访问连接器学到的地址。

在客户端查询域名，确认请求经过连接器的 DNS 接口：

```sh
tailscale dns query rogsoft.ddnsto.com
```

在连接器路由器上查看学习记录：

```sh
/koolshare/tailscale/current/tailscale --socket=/tmp/tailscale3/tailscaled.sock appc-routes --map
```

对查询结果里的目标 IP，Linux 用 `ip route get <目标IP>`、macOS 用 `route -n get <目标IP>` 查看实际路径。浏览器和路由器发起的是不同的连接，两者都需要可用的路径。最后刷新软件中心的列表与公告，并检查服务器是否响应：

```sh
curl --connect-timeout 5 --max-time 15 -sS -o /dev/null -w '%{http_code}\n' \
  'https://rogsoft.ddnsto.com/koolcenter/app.json.js'
```

#### 学习与维护

- 开启连接器或修改宣告列表后，插件会向本机连接器查询已分配的精确域名，让它尽快学习。访问规则拒绝这次自查、域名暂时无法解析或学习还没完成时，操作日志会提示，服务照常启动；之后客户端的查询还会继续触发学习。`*.` 开头的通配域名，要等客户端访问具体的主机名后才会学习。
- 应用与连接器无关的设置、重启服务，都不会清空学习记录。调整局域网、自定义网段或出口设置时，连接器已加入宣告列表的地址会保留。学习记录能否在核心重启后保留，还取决于控制面是否启用了 `AppCStoreRoutes`。
- 软件中心场景只用上面两个精确域名。`*.ddnsto.com` 还会覆盖其他用户的 DDNSTO 隧道，不适合放进这个应用的域名清单。
- 核心可能保留以前学到的旧地址，域名的解析结果变了，旧条目也不会马上全部撤下。不同域名共用同一个 IP 时，去往这个 IP 的连接都会走相同的路径。迁移或删除应用前，请检查域名清单、宣告列表和管理控制台里的批准状态。
- 已宣告的条目可能来自 LAN、自定义网段或连接器。自定义列表中的单个地址与连接器学到的地址重叠时，确认连接器工作正常后，可以删掉这个自定义条目，连接器会继续负责它。关闭连接器时，宣告列表按当前的 LAN、自定义网段和出口设置重新计算。

不用应用连接器的话，也可以在「高级：自定义网段」里宣告服务器当前 IP 的 `/32`（IPv6 用 `/128`），在管理控制台批准，并让访问端接受子网条目。这是固定地址的后备办法，服务器地址变了需要手动更新。

## 核心管理

1. 点「检查更新」，读取本项目签名的稳定版核心清单。
2. 有可用更新时点「更新核心」，在「操作日志」里查看进度和结果。
3. 更新后检查当前核心版本、连接状态和常用路由。
4. 需要恢复旧版本时，点「回退上一核心」（保留了上一核心时可用）。

- **更新时保留旧核心**：默认勾选，更新后保留被替换的核心作为回退目标。存储紧张时可以取消勾选，更新成功并通过检查后就删除旧核心，之后无法回退。这个选项在点「更新核心」时保存，不需要点「应用设置」。
- **清理旧版核心**：立即删除当前核心以外的所有核心，包括回退目标和中断的更新留下的文件。清理前会先校验当前核心，校验不通过就不删除任何核心。没有可删除的核心时，按钮不可用。

版本号后面的 `(rN)` 是本项目对同一上游版本的构建号，例如 `1.104.1 (r2)`；上游版本相同时，构建号越大表示构建配方越新。「原版核心」表示从原版插件沿用下来的程序。页面会显示回退目标；更新源提供的核心与当前核心相同时，「更新核心」不可用。

核心不会自动更新，需要你在页面上发起；升级插件也不会用安装包附带的核心替换已装的核心。本项目从 r2 构建起，核心不再包含 Tailscale 自带的自动更新、远程更新和 `tailscale update`；插件每次启动也会关闭核心的自动更新和更新提示。

### 更新过程

更新按设备架构下载核心，并校验 Ed25519 签名、SHA-256、版本、归档内容和 ELF 架构。

- **资源**：至少 64 MiB 可用内存；JFFS 要放得下新核心，另外留出 8 MiB 余量，目前约需 15 MB。空间不够时，先删除已无法回退到的核心，仍不够再删除上一核心，并在操作日志里说明；只有保留了可用的上一核心，才能手动回退。每次更新成功后，也会删除已无法回退到的核心。
- **下载线路**：更新清单和核心先从 GitHub 下载。连接失败、中途 30 秒收不到数据或 3 分钟内没下完时，改从镜像下载同一文件，镜像最多等 8 分钟，操作日志会注明用了镜像。镜像下载的内容按同样的规则校验。
- **切换**：切换核心会短暂中断连接。切换后检查本地服务、实际版本和设备身份，检查不通过时尝试恢复原核心和状态。恢复没完成时，页面报告失败并保留恢复记录；之后的启动或核心操作会先处理这条记录，安装和卸载会提示先完成恢复。

### 核心是怎么构建的

核心由本项目用 Tailscale 官方源码精简构建，不包含 Tailscale SSH、Taildrop 等功能；路由器自带的 SSH 由固件提供，不受影响。构建选项见[构建配方](../tools/core_recipe.json)，安装包附带哪个核心见[预装核心配置](../tools/bundled_core.json)，每个核心的源码和工具链记录在对应核心 Release 的元数据里。

## 状态与诊断

页面分别显示运行状态、Tailnet 连接、健康提示和接口流量。操作进行中时，页面显示「正在启动」「正在停止」「正在应用设置」或「正在切换核心」，完成后重新读取当前状态。状态显示未知或暂时读不到，不代表设备已经离线。

- 「连接详情」显示当前连接状态的摘要。
- 「网络检查」检查本地服务和 WAN，经 TLS 验证访问控制服务器的 HTTPS，并运行有时间上限的 Tailscale 网络探测。
- 「生成诊断摘要」显示实际核心版本、后端状态、健康信息、内存和存储概况，以及长度受限、已去掉凭据的近期运行日志。

诊断内容显示在「操作日志」区域，可以直接复制。诊断不会包含设备 state 文件、私钥或认证令牌。报告问题时，请附上固件和软件中心版本、插件和核心版本、复现步骤、相关的健康提示和诊断片段。

如果页面暂时收不到任务的回应，用「继续查询进度」检查原来的任务；只是日志读取失败时，用「重新读取日志」。先确认操作结果，再决定要不要重新操作。

任务记录已经失效、后台也确认没有操作在运行时，页面会停止跟踪，重新读取设置和状态，结果显示为「任务结果无法确认」。请核对当前设置后再决定是否重试。

## 自动维护

### 自动恢复

「自动恢复连接」默认开启。服务启用期间，维护任务每分钟运行一次；启动后的宽限期、连续失败确认、WAN 检查和恢复限额，用来避免不必要的重启。两次自动恢复至少间隔 30 分钟，任意连续 24 小时内最多尝试两次。

等待登录或审批、主动停用，以及短时间的网络波动，不会立即触发恢复。恢复只重启插件服务，保留设备身份，也保留你主动断开或登出的状态。地址变化和 NAT 重建后的规则维护不受这个开关影响。

### 防火墙规则

固件在 WAN 重连、修改防火墙设置等情况下会重建防火墙，整表替换原有规则，同时清除两类规则：

- **插件规则**：插件为局域网和 Tailnet 互访添加的转发和地址转换规则。
- **Tailscale 自身的规则**：Tailscale 服务运行后自己安装的规则，用于放行经 Tailscale 进入路由器的连接，以及子网和出口转发。这些规则被清除后，Tailscale 不会自己重新安装。

插件在固件的 NAT 事件中重新应用插件规则，并在每分钟的维护中核对这两类规则：

- 插件规则缺失时，直接重新应用。
- Tailscale 自身的规则缺失、且服务处于运行状态时，重启插件服务让 Tailscale 重新安装，通常一分钟内恢复。连续重启 3 次仍然缺失就停止尝试并写入日志，直到规则恢复、固件再次重建防火墙、手动应用设置或重启路由器。WAN 未连接时不重启，等恢复联网后再处理。

这项维护不占用自动恢复的次数，也不受「自动恢复连接」开关影响。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 安装提示平台不匹配 | 按机型选择安装包，或改用通用包；安装日志里有平台识别结果。 |
| 安装提示内存或存储不足 | 按日志确认缺的是哪种资源，清理无用文件后重试。所需空间见[安装前确认](#安装前确认)。 |
| 插件市场里的 Tailscale 显示「未安装」 | 正常：那是原版插件，与本插件的模块名不同。不要安装它，否则会覆盖本插件。 |
| 一直等待登录或设备审批 | 用页面上的「登录并授权」链接登录，并在管理控制台查看审批状态。 |
| 服务在运行，但子网或出口不通 | 检查管理控制台的路由批准和访问规则、客户端是否选择了出口、网段是否冲突，以及固件的转发规则。 |
| 检查或下载核心失败 | GitHub 失败后会自动改用镜像。日志提示两条线路都失败时，检查系统时间、DNS 和 HTTPS 连通性，并保留日志中的具体错误。 |
| 提示另一个操作正在进行 | 等当前任务完成后再查询状态。启停、设置、安装、核心操作和诊断共用同一个操作锁。 |
| 页面提示读取失败或超时 | 页面会自动重试。一直失败时，重新打开插件页面，确认路由器的登录会话仍然有效；记下提示内容和固件、插件版本，方便排查。 |
| 提示需要恢复核心事务 | 保留任务日志，通过启动服务或再次进行核心操作来重试恢复。不要手动删除恢复记录后继续安装。 |
| 页面和管理控制台显示已连接，但无法经 Tailscale 访问路由器 | 多半是固件重建防火墙清掉了 Tailscale 自身的规则，插件会在一分钟内自动重启服务恢复。如果日志提示已停止自动修复，请生成诊断摘要并检查固件防火墙。 |
| 路由器重启后服务没有启动 | 在固件系统日志里搜索 `tailscale-plugin`，看启动请求是否失败或等待超时；点「应用设置」可以手动启动。 |
| 连接持续异常 | 重启之前先记下健康提示和诊断日志，检查 WAN、资源和固件网络配置；报告问题时需要的信息见[测试指南](TESTING.md#问题记录)。 |

## 卸载

在软件中心卸载插件会停止服务，删除插件程序和全部核心。设备身份和设置都会保留，重新安装后可以直接使用。

要连设备身份一起清除，卸载后删除 `/koolshare/configs/tailscale` 目录；之后重新安装需要重新登录授权，路由器会作为新设备加入 Tailnet。

上次的核心操作还没恢复时，卸载会被拒绝。请先在插件页面重试核心操作，查看操作日志后再卸载。
